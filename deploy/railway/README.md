# Railway deployment (developer-preview demo)

Services (project "serk-retail-demo"):

| Service | Source | Notes |
|---|---|---|
| `MariaDB` | `mariadb:10.11` (template Onvy0F, image pinned) | volume `/var/lib/mysql`; utf8mb4 start flags; root password generated by Railway |
| `Redis` | Railway Redis template | cache + queue (single instance) |
| `serk-retail` | this repo, `deploy/railway/Dockerfile` | volume `/data` (sites, secrets, logs) |

App variables (references, no literal secrets):

```
DB_HOST=${{MariaDB.RAILWAY_PRIVATE_DOMAIN}}
DB_PORT=3306
DB_ROOT_PASSWORD=${{MariaDB.MARIADB_ROOT_PASSWORD}}
REDIS_URL=${{Redis.REDIS_URL}}
PUBLIC_URL=https://${{RAILWAY_PUBLIC_DOMAIN}}
SITE_NAME=serk-demo.local
SERK_DEMO_SEED=1
DATA_DIR=/data
```

First boot creates the site (~3–6 min) and loads **fictional** SERK Demo Mart data.
Credentials are written to `/data/secrets/` only. Read them with:

```
railway ssh --service serk-retail cat /data/secrets/administrator_password
railway ssh --service serk-retail cat /data/secrets/demo_user_credentials
```

Limits: one container runs web + worker + scheduler; no socket.io (no realtime desk updates);
no PDF engine (wkhtmltopdf not installed); single MariaDB without replicas; backups are
Railway volume backups only. Not a production topology (see ADR-007).
