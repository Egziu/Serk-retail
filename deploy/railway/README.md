# Railway deployment (developer-preview demo)

Services (project "serk-retail-demo"):

| Service | Source | Notes |
|---|---|---|
| `MariaDB` | `mariadb:10.11` (image pinned) | volume `/var/lib/mysql`; utf8mb4 start flags; root password generated by Railway; **private network only (no public TCP proxy)** |
| `Redis` | `redis:8.2` | cache + queue (single instance); volume `/data` |
| `serk-retail` | this repo, `deploy/railway/Dockerfile` | volume `/data` (sites, secrets, logs); healthcheck `/api/method/ping` |

App variables (references; the two passwords are the only literal secrets and are set in Railway, never in the repo):

```
DB_HOST=${{MariaDB.RAILWAY_PRIVATE_DOMAIN}}
DB_PORT=3306
DB_ROOT_PASSWORD=${{MariaDB.MARIADB_ROOT_PASSWORD}}
REDIS_URL=${{Redis.REDIS_URL}}
PUBLIC_URL=https://${{RAILWAY_PUBLIC_DOMAIN}}
SITE_NAME=serk-demo.local
SERK_DEMO_SEED=1
DATA_DIR=/data
SERK_ADMIN_PASSWORD=<generated, >= 12 chars>     # optional; Administrator
SERK_DEMO_PASSWORD=<generated, >= 12 chars>      # optional; shared by the 5 fictional demo users
```

First boot creates the site (~3–6 min) and loads **fictional** SERK Demo Mart data.

Passwords: if `SERK_ADMIN_PASSWORD` / `SERK_DEMO_PASSWORD` are set, they are applied on **every**
boot (change the variable and redeploy to rotate; this also overwrites a password changed in the
app). If unset, random passwords are generated on first boot. Current values are always written to
`/data/secrets/` (0600) and never to the logs:

```
railway ssh --service serk-retail cat /data/secrets/administrator_password
railway ssh --service serk-retail cat /data/secrets/demo_user_credentials
```

Demo users (fictional): `cashier1@serk.test` (Lane 1), `cashier2@serk.test` (Lane 2),
`supervisor@serk.test`, `manager@serk.test`, `receiver@serk.test`.

Web serving: there is no nginx in the image, so gunicorn runs `serk_wsgi:application`, which wraps
Frappe with its own static middleware (`/assets`, public `/files`) and `ProxyFix` for Railway's edge.
Plain `frappe.app:application` would 404 every asset and the desk would load without CSS/JS.

Limits: one container runs web + worker + scheduler; no socket.io (no realtime desk updates);
no PDF engine (wkhtmltopdf not installed); single MariaDB without replicas; backups are
Railway volume backups only; approvals lock after 5 failed supervisor passwords for 15 minutes.
Not a production topology (see ADR-007).
